# UT (メルカリの新品 UNIQLO/GU) の運用 — 出して終わりにしない (2026-09-12 設計)

目的 (ユーザー確定 2026-09-11): **公式では買えない UT を、メルカリの新品未使用で出す**。
PSA と同じ運用にする = 出品は通過点で、**補URL・二重出品・再仕入れ・値段・需要の還流**まで回す。

## 全体の流れ (PSA との対応)

| 段 | UT | PSA | 動かすもの |
|---|---|---|---|
| ① 集める | 抽出くん: カタログの**公式売切**コラボ名で検索 | mercari PSA10 収集 | 夜間 (抽出くん) |
| ② 目視で特定 | `ut_identify.py` (公式画像と見比べて商品+色) | `newcand_confirm` (絵柄で版) | 🩹 UT 新品 目視特定 |
| ③ 出品行に足す | 商品管理シート Tシャツ行 (B空) + 台帳 | `plan_high_rows` | ② の確定時 |
| ④ 出品 | `tshirt_listing` (カタログの値を写す) | `psa_to_csv` | Tシャツ 新規 |
| ⑤ itemID 書戻し | `itemid_writeback_audit` (SKU=メルカリID) | 同じ | 🤖自動 / 入稿後 |
| ⑥ **KEY を書く** | 出品済み行に `uniqlo_ut:<pid>:<色>:<サイズ>` | `key_backfill_live` (cert→KEY) | 夜間 |
| ⑦ **二重出品を止める** | 同じ KEY が出品済みなら出さず、**補URLに回す** | 重複くん + KEY | ④ の中 |
| ⑧ 補URL (予備の仕入元) | `ut_hoju_fill search/confirm` | `psa_hoju_fill` | 夜間 + 🩹目視 |
| ⑨ 売り切れ → 数量0 | 監視くん (メルカリの売切を見る) | 同じ | 監視くん巡回 |
| ⑩ 再仕入れ | `ut_hoju_fill restock-*` → 数量戻す | PSA 再仕入れ ①②③ | 🛒 UT 再仕入れ |

| ⑫ 需要の還流 | ファネルの売れ筋/死筋 → ①の検索語 | demand_winners | 夜間 |

## 決めごと (なぜそうするか)

- **KEY は出品してから書く**。出品前の行に KEY があると重複くんが「出品済み」と読んで、
  その商品を二度と出せなくする (orphan KEY 事故)。書く先は AI列、書くのは B列 (itemID) が
  埋まった行だけ。
- **KEY に 色とサイズを入れる**。PSA は「カード1枚=1出品」だが、UT は同じ柄でも
  色・サイズで別の出品になる (1出品=1サイズ)。`uniqlo_ut:E480691-000:BLUE:3XL`。
- **同じ KEY が出品済みなら出さない**。捨てずに、その出品の**補URL**として足す
  (無在庫なので仕入元は多いほど強い。PSA の「2つ目は補URLへ」と同じ)。
- **特定は人**。機械は候補を並べるだけ (2026-08-22 ユーザー確定)。タグの番号は候補の順番にしか使わない。
- **止まる時は出さない**。素材の訳が無い / 作品名が対応表に無い / サイズが決まらない /
  色がカタログに無い → その行は出さない (推測で出品しない)。
- **公式で買える物は対象外**。目的が「公式では買えない物」なので、候補から外す。
